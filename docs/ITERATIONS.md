# Последовательные улучшения FaceFlow

## 1. Повтор частичной загрузки - 5 октября 2026

Наблюдение: загрузчик сбрасывал выбор после любых ответов и считал дубликаты загруженными. После сетевой ошибки приходилось заново выбирать файлы. Источник: предыдущая версия [web/app.js](../web/app.js), commit `46f1901`.

Изменение: неудачные файлы остаются в выборе, кнопка повторяет только их. Новые файлы, дубликаты и ошибки имеют отдельные счётчики. Во время загрузки выбор заблокирован; новый выбор очищает старые ошибки. Файлы сохраняются только в памяти вкладки; перезагрузка их сбрасывает. [Клиент](../web/app.js).

Проверка: реальная смешанная загрузка в локальном браузере - синтетический кадр, дубликат и повреждённый файл; повтор отправил только повреждённый файл. Node-тесты с подменёнными DOM/API проверяют временную ошибку с успешным повтором, защиту от двойного запуска и смены выборки. Все 8 Python-интеграционных тестов с реальными моделями прошли локально. [Тесты клиента](../tests/test_upload.cjs), [интеграционные тесты](../tests/test_flow.py).

Вывод: успешные файлы повторно отправлять не нужно; ошибка формата требует выбора другого файла. Это проверка сценария, не исследование удобства у фотографов. Следующий приоритет: ограничить PATCH публикации только статусом, чтобы не перезаписывать настройки устаревшим снимком клиента.

Опубликован commit `93881f1`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37241638965).

## 2. Сохранность настроек между действиями - 5 октября 2026

Наблюдение: публикация отправляла старые название, описание и режим обработки, а сохранение настроек отправляло старый статус. Вторая вкладка могла перезаписать правки первой или отменить паузу. Источник: [web/app.js](../web/app.js), версия `93881f1`.

Изменение: публикация меняет только status, сохранение настроек - только title/description/detailed. Описание ограничено 2000 символами и в UI, и в API; заголовок обновляется из ответа сервера. [Клиент](../web/app.js), [контракт](API.md).

Проверка: в двух реальных вкладках сохранены новые название/описание, затем выполнена публикация из старой вкладки; данные сохранились. Пауза из второй вкладки сохранилась после записи настроек из первой. Локально прошли 4 Node-теста с подменой DOM/API и 9 Python-интеграционных тестов, включая границы описания и сохранение несвязанных полей. [Клиентские проверки](../tests/test_settings.cjs), [API-проверки](../tests/test_flow.py).

Вывод: разные действия не должны отправлять чужие поля. Одновременное редактирование одного и того же поля остаётся без контроля версий; это отдельное ограничение. Следующий приоритет: гостевая страница не возобновляет поиск после снятия паузы без перезагрузки; ошибка фоновой проверки готовности теряется молча.

Опубликован commit `16ca6d0`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37241784060).

## 3. Проверка готовности гостевой галереи - 5 октября 2026

Наблюдение: draft/paused блокировали поиск без способа обновить состояние в форме; сетевые ошибки автоматической проверки pending игнорировались. Источник: [web/app.js](../web/app.js), версия `16ca6d0`.

Изменение: кнопка «Проверить готовность» для недоступной галереи и ошибок проверки. Обновление сохраняет селфи/согласие и название берёт из ответа. Pending продолжает штатную автоматическую проверку; после ошибки таймер останавливается и пользователь может повторить. Параллельные проверки не запускаются. [Клиент](../web/app.js).

Проверка: реальная локальная галерея paused → published, выбранное синтетическое селфи и согласие сохранились, следующий поиск нашёл кадр. На 390×844 кнопка помещается в карточку и доступна. 7 Node-тестов прошли; ошибки сети/таймеры проверены с подменой API, не реальным обрывом соединения. [Проверки](../tests/test_readiness.cjs).

Вывод: ожидание должно иметь видимый способ восстановления. Следующий приоритет: защита от смены селфи во время поиска и от перехода назад во время пакетной загрузки; старый ответ не должен попасть в другой экран.

Опубликован commit `4d1bd37`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37241893173).

## 4. Защита выполняемых действий - 5 октября 2026

Наблюдение: выбранное селфи можно было сменить до ответа поиска; интерфейс мог показать результат предыдущего лица рядом с новым селфи. Возврат к съёмкам во время загрузки оставлял обработчик на другом экране. [Клиент](../web/app.js), версия `4d1bd37`.

Изменение: поиск блокирует селфи/согласие, повторную отправку и проверку готовности, затем восстанавливает ввод. 403/409 показывают проверку готовности. Загрузка блокирует возврат, удаление съёмки и переход по логотипу; уход/перезагрузка вкладки запрашивают штатное предупреждение браузера. [Клиент](../web/app.js).

Браузерная проверка также выявила: CSS display перекрывал атрибут hidden. Теперь скрытые элементы действительно скрыты, включая ZIP после отклонения всех кадров. [CSS](../web/style.css).

Проверка: 10 Node-тестов с подменёнными DOM/API прошли; задержанный запрос не допускает второго поиска, ошибки освобождают ввод, 403/409 блокируют поиск до проверки готовности. Реальный браузер подтвердил отключённые селфи/согласие во время OpenCV поиска, восстановление после паузы в другой вкладке и исчезновение ZIP/выбора после «Это не я» для всех кадров. Фокусный risk-reviewer не доказал существенных внесённых ошибок. Системный диалог beforeunload отдельно не проверен; это предупреждение, не гарантия сохранения очереди при закрытии браузера. [Тесты поиска](../tests/test_search.cjs), [загрузки](../tests/test_upload.cjs).

Вывод: ввод и навигация должны соответствовать выполняемому действию. Следующий приоритет: проверить доступность просмотра фотографий с клавиатуры и возврат фокуса, не менять визуальный стиль без причины.

Опубликован commit `91686a0`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37242057783). Следующий выбранный приоритет уточнён до истечения ссылок: клавиатурные стрелки уже реализованы, нового дефекта просмотра не доказано.

## 5. Истечение ссылок и обновление подборки - 5 октября 2026

Наблюдение: сервер выдаёт билеты на 1200 секунд, клиент не использовал expires_in и продолжал предлагать старые скачивания без объяснения. [API](API.md), [app.py: search/access_ticket](../app.py), версия `91686a0`.

Изменение: показан срок скачивания и кнопка обновления подборки с сохранённым селфи/согласием. После истечения ссылки и действия старой подборки отключаются; открытый просмотрщик закрывается. Проверка на клике защищает и после задержки таймера фоновой вкладки. Обновление начинает новый поиск и сбрасывает выбор кадров; повторная проверка глазами нужна. Клиентский срок - подсказка, сервер остаётся проверкой доступа. [Клиент](../web/app.js).

Проверка: 10 интеграционных Python-тестов прошли, включая реально подписанный просроченный ticket (сдвинут только timestamp создания), запрет фото/ZIP/feedback и успешный новый поиск. 14 Node-тестов с подменёнными DOM/API и временем прошли, включая истечение, задержанный таймер и замену результатов. Реальный браузер проверил срок и повтор поиска без выбора селфи; размеры desktop и 390×844. Не ждали 20 минут в браузере; истечение UI проверено управляемым временем в Node. [Серверные тесты](../tests/test_flow.py), [клиентские тесты](../tests/test_expiry.cjs).

Risk-reviewer воспроизвёл гонку: старый feedback после обновления мог отключить новую подборку. Исправлена проверкой identity активной галереи до изменений и после await; регрессионный тест проходит. Reviewer подтвердил исправление, включая callback просмотрщика. [Клиент и тест](../tests/test_expiry.cjs).

Вывод: срок доступа должен быть виден, а старые ответы не должны влиять на новый поиск. Следующий приоритет: адресная проверка ошибочного JSON в PATCH статуса; список вместо строки сейчас может дать 500 вместо ошибки ввода.

Опубликован commit `b5e35f4`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37242526972).

## 6. Проверка типа статуса - 5 октября 2026

Наблюдение: PATCH с массивом или объектом в status возвращал 500: проверка принадлежности множеству вызывала TypeError. Новый тест воспроизвёл оба случая до исправления. [Обработчик](../app.py), версия `b5e35f4`; [регрессионный тест](../tests/test_flow.py).

Изменение: перед проверкой допустимых значений проверяется строковый тип. Неверные status возвращают 400; остальные поля того же отклонённого запроса не записываются. Допустимые статусы и клиентский контракт сохранены. [Обработчик](../app.py).

Проверка: все 11 Python-интеграционных тестов прошли локально. Новый тест проверяет массив, объект, null, boolean, число и неизвестную строку, ответ JSON и сохранность названия/статуса; действующий lifecycle проверяет публикацию и паузу. UI не менялся. [Тесты](../tests/test_flow.py).

Опубликован commit `1e9bb8e`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37242660184).

## 7. Повторные действия с публикацией и ссылкой - 5 октября 2026

Наблюдение: при задержанном API кнопки отправляли повторные запросы. Каждый rotate-link создаёт новый ключ и отзывает предыдущий; повторные операции также могли конкурировать со сменой статуса. Тест задержанного ответа воспроизвёл несколько запросов до исправления. [Клиент](../web/app.js), версия `1e9bb8e`; [сервер rotate_link](../app.py); [регрессионные тесты](../tests/test_settings.cjs).

Изменение: публикация, пауза и обновление ссылки выполняются по одному. Кнопки блока заблокированы до завершения, включая подтверждение; фоновая перерисовка не снимает блокировку. Ошибка или отмена возвращают доступные действия. Запоздалый ответ после перехода в другую съёмку не обновляет её экран. PATCH по-прежнему отправляет только status. [Клиент](../web/app.js).

Проверка: клиентские тесты с подменёнными DOM/API подтверждают повтор, конкурирующее действие, фоновую перерисовку, ошибку, отмену и смену экрана. Реальный локальный браузер на синтетической галерее подтвердил блокировку кнопок при подтверждении, отмену, новую ссылку, паузу и повторную публикацию. Задержка и сбой сети проверены в Node, без реального отключения сети. [Тесты](../tests/test_settings.cjs).

Опубликован commit `d01096b`; [CI окончательного HEAD успешен](https://github.com/malyarq/faceflow/actions/runs/37242946732).

## 8. Восстановление гостевого доступа - 5 октября 2026

Наблюдение: ошибка первого открытия не имела повтора; отозванный ключ предлагал проверять готовность, хотя это не возвращает доступ. В браузере также доказано: переход к новой ссылке той же съёмки меняет hash, но клиент продолжает использовать старый guestKey. [Клиент](../web/app.js), версия `d01096b`; [проверка ключа](../app.py).

Изменение: временную ошибку открытия можно повторить без перезагрузки, повторные нажатия заблокированы. Для 403/404 показаны конкретные дальнейшие действия без бесполезной проверки готовности; причина отзыва или удаления не утверждается. При изменении гостевого ключа в hash страница перечитывает доступ. Это новое открытие: выбранное селфи и старая подборка сбрасываются. Смена остальных параметров hash перезагрузку не вызывает. API и серверная проверка доступа сохранены. [Клиент](../web/app.js).

Проверка: Node-тесты подтверждают временный сбой, успешный и повторно неудачный повтор, отсутствие параллельных запросов, 403/404 при открытии/проверке/поиске и изменение ключа. Реальный браузер получил один специально подставленный локальным тестовым сервером HTTP 503; кнопка повтора затем открыла настоящую форму. В той же вкладке проверены переходы между действующим и отозванным ключами без ручной перезагрузки. Текст доступен на 390×844. Сбой HTTP 503 — контролируемая проверка, не реальное отключение сети. [Тесты готовности и открытия](../tests/test_readiness.cjs), [поиска](../tests/test_search.cjs).

## 9. Ошибка отметки после истечения ссылки - 5 октября 2026

Наблюдение: запрос «Не я», начатый до истечения ссылки, при запоздалой ошибке снова включал кнопку просроченного результата. Если таймер задерживался в фоновой вкладке, обработчик ошибки также не проверял срок. Две новые проверки воспроизвели ошибку на исходном коде. [Клиент](../web/app.js), базовый HEAD `8a0238b`; [регрессионные тесты](../tests/test_expiry.cjs).

Изменение: перед возвратом кнопки и выводом ошибки проверяются текущая подборка и срок ссылки. Просроченный результат остаётся заблокированным; ошибка старого результата не меняет новый экран. До истечения ссылки повтор остаётся доступен. API не менялся. [Обработчик результатов](../web/app.js), [контракт feedback](API.md).

Проверка: все 25 клиентских Node-тестов прошли, включая четыре новых случая: истечение с таймером и без него, ошибка до истечения и ошибка после новой подборки. Проверены синтаксис JavaScript и git diff --check. Использованы подменённые DOM/API и управляемое время; браузер для этой точечной правки не запускался. [Тесты](../tests/test_expiry.cjs). Итоговый CI доступен в проверках PR ветки `codex/feedback-expiry`.

Тесты теперь выполняют настоящий refreshViewer вместе с results; прежние проверки запоздалых ответов и истечения также прошли. Адресное ревью охватило оба вызывающих обработчика, finally, навигацию просмотрщика и замену подборки. Проверены синтаксис и diff. Использованы подменённые DOM/API и время; реальный браузер не запускался. [Тесты](../tests/test_expiry.cjs).
